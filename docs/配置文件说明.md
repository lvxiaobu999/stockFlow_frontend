# 配置文件说明

部分配置文件必须保持 JSON/JSONC 结构，不能安全地写入团队说明性注释，因此将用途集中记录在本文档。

## `src/styles/index.css`（Tailwind v4 入口）

- Tailwind v4 采用 CSS 优先配置：入口通过 `@import 'tailwindcss'` 引入，项目不再有 `tailwind.config.ts` 和 `postcss.config.cjs`。
- 主题令牌写在 `@theme` 块中：`--color-brand-*` 是项目级品牌色（对应 `bg-brand-500`、`text-brand-600` 等工具类），`--shadow-panel` 是通用面板阴影；Ant Design 组件颜色仍通过 `ConfigProvider` 管理。
- v4 自动扫描源码文件（遵循 `.gitignore`），无需手动维护 `content` 列表；新增 feature 文件类型不再需要同步配置。
- 文件顶部的 `@layer theme, base, components, antd, utilities;` 声明级联层顺序：antd 样式经 `AppProviders` 中的 `StyleProvider layer` 收进 `antd` 层，且排在 `utilities` 之前，因此 `text-brand-600` 这类工具类可以直接覆盖 antd 组件样式，无需 `!important`。
- Tailwind 插件只放跨业务复用的插件，单页面样式优先使用 Tailwind class 或组件 CSS。

## `stylelint.config.mjs` / `.stylelintignore`

- `stylelint-config-standard` 提供 CSS 标准规则；`@dreamsicle.io/stylelint-config-tailwindcss` 将 `@theme`、`@apply` 等 Tailwind v4 指令注册为合法语法，避免 `at-rule-no-unknown` 误报。
- `.less` 文件（`App.less`）通过 `postcss-less` 语法解析，支持嵌套与 `//` 行注释。
- 运行 `pnpm lint:css` 校验 `src/**/*.{css,less}`；忽略范围与 `.prettierignore` 保持一致。

## `vite.config.ts`

- `loadEnv(mode, process.cwd(), '')` 读取 `.env` 和 mode-specific 环境文件。
- `@` alias 映射到 `src`，应用代码统一使用 `@/*` 导入。
- `tailwindcss()`（`@tailwindcss/vite`）负责编译 Tailwind，替代 v3 时代的 postcss + autoprefixer 链路。
- `server` 和 `preview` 使用独立端口，`strictPort` 避免端口被占用时静默换端口。
- `build.target` 控制生产代码的浏览器基线；`manualChunks` 将 Ant Design 和 Router 拆到稳定 vendor chunk。
- `define.__APP_VERSION__` 是构建时元数据，不得放入 token、密钥等敏感信息。

## JSON/JSONC 配置

- `tsconfig*.json`：TypeScript 项目引用、路径别名、严格未使用检查和 bundler 模式。根 `tsconfig.json` 只负责引用 app/node 两个子项目。
- `.oxlintrc.json`：Oxlint 插件、忽略目录和规则；修改规则时应同步评估 `pnpm lint` 的 CI 时间。
- `.prettierrc.json`：统一无分号、单引号、尾逗号、打印宽度和 Tailwind class 排序；`tailwindStylesheet` 指向 v4 CSS 入口，供 prettier-plugin-tailwindcss 读取主题。
- `package.json`：脚本、依赖和 lint-staged；不要把业务配置写入 package scripts，业务配置放 `src/config`。
