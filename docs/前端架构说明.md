# StockFlow 前端架构说明

## 分层原则

依赖方向保持单向：`pages -> features/components -> services/stores`。布局和路由属于应用编排层，不承载具体业务规则。

- `app/`：全局 Provider、错误边界、应用启动相关能力。
- `layouts/`：侧边栏、顶栏和 Outlet；导航项来自 `config/navigation.tsx` 的单一配置源。
- `router/`：只描述 URL 到页面的映射。页面本身通过懒加载拆分。
- `features/<domain>/`：业务垂直切片。`types.ts` 定义领域模型，`services/` 负责数据访问，`hooks/` 负责页面数据编排，`components/` 负责领域 UI。
- `components/`：不依赖具体业务的通用组件，如页面头、统计卡、反馈状态。
- `services/`：全局基础设施。禁止在展示组件中直接调用 Axios 或 `fetch`。
- `stores/`：Zustand 全局状态。服务端数据由 TanStack Query 管理，不复制到全局 store。
- `utils/`：纯函数工具方法，不依赖 React、路由、Ant Design 或具体业务状态。

## 多级业务目录怎么组织（架构建议）

这不是强制规范，而是我对进销存中大型后台的推荐：`features` 和 `pages` 都可以是树形结构，但两者职责不同。先按业务复杂度选择，简单模块保持扁平，复杂模块再逐层拆分：

```text
src/
├─ features/
│  └─ inventory/
│     ├─ overview/              # 库存总览领域切片（需要复杂化时再拆）
│     │  ├─ components/
│     │  ├─ hooks/
│     │  ├─ services/
│     │  └─ types.ts
│     ├─ records/                # 出入库记录领域切片
│     │  ├─ components/
│     │  ├─ hooks/
│     │  ├─ services/
│     │  └─ types.ts
│     └─ index.ts
└─ pages/
   └─ inventory/
      ├─ InventoryOverviewPage.tsx
      └─ InventoryRecordsPage.tsx
```

推荐规则：

1. `features/inventory` 表示库存这个业务域；`overview`、`records` 表示库存域下的子模块。
2. `pages/inventory` 只放路由入口页面，负责组合对应 feature，不放请求和复杂业务逻辑。
3. 子模块很简单时可以先直接放在 `features/inventory/components`、`hooks`、`services`，不要为了目录而目录；复杂后再下沉为 `overview/`、`records/`。
4. 路由、侧边栏路径和标题统一来自 `src/config/routes.ts`，避免页面和菜单重复维护字符串。

## 数据与状态边界

- Axios 实例统一位于 `src/services/httpClient.ts`，feature service 只负责描述接口和响应类型。
- TanStack Query 负责服务端数据缓存、请求状态、失效和刷新；query key 放在对应 feature 的 hooks 中。
- Zustand 只保存跨路由的 UI/会话状态。`useAppStore` 持久化侧边栏偏好，`useAuthStore` 保持内存会话，不保存敏感 token。
- Mock 使用 MSW：开发环境 `VITE_USE_MOCK_API=true` 时，`src/mocks/handlers.ts` 拦截 Axios 请求；关闭后同一 service 自动请求真实 API。

## 新增业务功能流程

1. 在 `src/features/<domain>/types.ts` 定义请求、响应和领域模型。
2. 在 `services/` 创建 typed service，并通过 `apiClient` 访问接口。
3. 在 `mocks/handlers.ts` 增加同路径 mock，保持与真实响应一致。
4. 在 `hooks/` 使用 `useQuery`/`useMutation` 封装加载、错误、刷新和失效策略。
5. 在 `components/` 拆分领域视图；页面只做布局和组合。
6. 在 `router/index.tsx` 注册页面，并用 `Suspense` 包裹较重页面。
7. 如需侧边栏入口，只更新 `config/navigation.tsx` 和 `config/routes.ts`。

## 质量门禁

本地提交由 Husky 执行：

- `commit-msg`：commitlint conventional 规范。
- `pre-commit`：lint-staged 对暂存文件运行 Prettier 和 Oxlint。

CI 应至少执行 `pnpm typecheck`、`pnpm lint`、`pnpm build` 和 `pnpm format:check`。
